# tcslog 0.4.2

**Upgrade if you read logs that may be damaged.** A reader in 0.4.1 or
earlier could return a record that was never written: when a segment file
was cut short in the middle of a session and the next file's `remaining`
field happened to match, it joined the front of one record to the tail of a
later one. 0.4.2 reports the loss instead, as `ReadTruncated` with `lost` of
zero. Fuzzing found it; a regression test and two fuzz targets, run in CI,
now guard it.

**Nobody has to change anything.** No interface changes in Rust, C/C++ or
Python 3, and a caret requirement on 0.4 matches 0.4.2. Reading also no
longer allocates on its first segment file, as the documentation always
promised.

Stored format: unchanged, 0.1.0.

### Fixed

- **The reader could return a record that was never written.** A segment
  file cut short in the middle of a session -- by a failed write or a damaged
  sector -- went undetected when the next file's `remaining` field happened
  to equal what the record being read still owed. The reader then spliced
  the next file's bytes, the tail of a later record, onto the front of the
  current one, and returned the result as a whole record or as the bytes of
  a `ReadOverflow`. The reader now requires every segment file it leaves for
  another of the same session to have held a full data section, as every
  file but a session's last does, and reports `ReadTruncated` with `lost` of
  zero when one did not. Found by fuzzing, and covered by a new API test.
- Reading allocated once, the first time it opened a segment file whose
  name was longer than the placeholder its path buffer started with, though
  the documentation promises reading allocates nothing. The buffer is now
  reserved at open.

### Added

- `fuzz/`, two cargo-fuzz targets for the reader, run by `make fuzz` and for
  a minute each in CI. `damaged_log` writes real logs, damages them, and
  requires that the reader invent nothing when the damage only removes
  bytes; `arbitrary_files` builds logs from raw bytes and from accepted
  headers around arbitrary fields. Both require that the reader never panic
  and always reach the end.
- `tcslog/tests/no_alloc.rs`, which holds writing and reading to their
  promise of no allocation with a counting allocator, across rolls, across
  segment files, and past a lost one.
- `make check` checks the fuzz crate's formatting and clippy.

### Changed

- The user manual is `docs/manual.rst`, renamed from `docs/tcslog.rst`, and
  `make -C docs` renders it to `docs/manual.html`.

### Notes

- Three interfaces to the same library: the Rust API in the `tcslog` crate;
  the C ABI in `tcslog-c`, with `tcslog.h` for C and C++ and `tcslog.hpp` for
  C++; and the Python 3 package in `tcslog-py`. The C library and the Python
  package are built from a checkout; `make install` installs them.
- User documentation is `docs/manual.rst`, which covers all three languages,
  and the design specification is `docs/design.rst`.
- Requires Rust 1.75 or later, and Python 3.8 or later for the Python
  package. Dual licensed under MIT OR Apache-2.0.
